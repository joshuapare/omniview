Cilium resource editors · review proposal

Isolated interactive HTML mock. No production React, cluster connection, API mutation, controller health, or mock approval claimed.

Run

Serve this asset directory with any static HTTP server and open index.html. No dependency install or build required. Vendor contains existing yaml 2.7.1 browser parser with license.

Grounding

Cilium v1.18.0 commit 274205f001bb24b89d19f0fe7c3fb3aca20030c2. Every resource links its pinned CRD below. Served storage versions and namespace scopes come from those CRDs. BGP v2 is distinct from deprecated v2alpha1 CiliumBGPPeeringPolicy. This mock does not migrate them.

Approved density and interaction workflow: omniviewdev/omniview issues 249 and 262; Kubernetes plugin PR72/74. ResourceManifestEditor.tsx lines 39–95 supplied source-draft, destination and mode semantics. No named mock skill is installed. web-design-guidelines skill reviewed the known prototype against its fetched command.md rules.

Shared frame & reuse

1000×700 frame, 32px controls, 13px body, 20×24 padding, 16px gaps. Faithful HTML composition targets existing Dialog, FormField, Input, Select, Checkbox, Button, NumberInput, EditableList/Table, Tooltip/Popover and SegmentedControl; production uses semantic base-ui tokens. This isolated mock uses approximate colors, not imported React components. No new generic primitive is proposed. Cilium add-on provider owns semantics; Kubernetes host owns lifecycle and destination, not a hardcoded 22-kind form registry.

Boundaries

  • Create/edit only user-authored objects with installed matching CRD, allowed verbs and confirmed feature support. Fixture ready is a simulated capability, not discovered permission.
  • metadata.name and namespace lock during edit. Status and controller outputs are never owned.
  • CiliumLocalRedirectPolicy redirectFrontend, redirectBackend and skipRedirectFromBackend are immutable under CRD CEL rules. Guided edit and source are read-only; no delete/recreate shortcut.
  • Generated CiliumEndpoint, CiliumEndpointSlice, CiliumIdentity, CiliumNode and CiliumBGPNodeConfig are inspection-only. Owner navigation is explicitly unavailable in fixture; no diagnostics/logs/dashboard rebuilt.
  • User-owned Envoy configuration has advanced authoring; controller-owned Envoy is inspect-only. Arbitrary xDS resource structure stays expert source-owned.
  • Policy selection changes may isolate workloads. Routing, pool, announcement and peer changes can interrupt traffic. Review is non-mutating and keeps destination visible.
  • Feature installation is separate: BGP Control Plane, Egress Gateway, Local Redirect, L2 announcements, multi-pool IPAM, Gateway API and Envoy support require administrator confirmation. Schemas alone establish none of these.
  • Egress IP and interface are mutually exclusive. Guided fixture uses egressIP only. Interface or multiple-gateway variants remain source-authored. Egress IP must exist on gateway device; no allocation occurs.
  • Service, Secret and peer names are editable unresolved references, not verified resources. No resolved Secret values are fetched. No references, denied, missing CRD and unverified feature are distinct fixture states.

Source behavior & honest limits

Single in-memory source. YAML parser locates existing owned nodes; control edits splice changed node ranges only. Browser proof retains comments, unknown scalar strings and a large integer exactly while editing a sibling name. Invalid source stays exact and blocks Form. Mode alone persists; resource drafts never persist.

Bounded mock, not production schema validation: first structured policy/router/peer row is demonstrated. Additional rules, deny branches, matchExpressions, dual stack variants, backend/address unions, arbitrary xDS, optional fields omitted from fixture and full schema constraints stay source-authored. Existing-node splice proof does not establish general alias/anchor, nested collection-comment, newly inserted missing-path or all-scalar round-trip support. Production adapter must retain safe source-only fallback for those cases. No full CIDR, BGP timer, range overlap, reference, xDS or admission validation claim. Current visible local validation exercises resource name and malformed source. Fixture presets illustrate layout, not executable defaults.

Form labels are task-oriented; exact manifest paths stay beside controls for administrators. Advanced fields currently exposes the same bounded owned-path set, not a second schema dump. Source exposes remaining real manifest; source review never implies valid reconciliation.

Browser evidence

88 screenshots: each of 17 authoring kinds has initial, edit, review and source; five generated kinds have inspect and unavailable-owner navigation; ten shared safety/help/preservation/availability/narrow states.
