Scope: Kubernetes v1.35.0; apiextensions.k8s.io/v1; CRD is cluster-scoped even when instances are Namespaced. Built-in Kubernetes plugin adapter owns native CRD administration. Custom resource instances remain owned by their own groups and installed providers; no dynamic instance form is implied. ConversionReview is webhook protocol, never a Create resource.

Read-only status panel -> status.conditions, status.acceptedNames, status.storedVersions and gate-dependent observedGeneration. Status never authored or submitted.
Ownership panel -> external field manager fixture only. No force-ownership control.
Availability panel -> explicit simulation of missing discovery, create/update denied, Service lookup denied/unavailable/empty and unsupported version. They do not execute authorization or disable a real API action because no API action exists.

Shared composition: Dialog, FormField, Input, Select, Checkbox, RadioGroup, SegmentedControl, Tooltip/Popover, Table, Buttons, TextArea and existing source-editor surface. No new generic base-ui component or release proposed. Kubernetes semantics and validation stay in adapter. 1000x700 compact reference frame, 32px inputs, 13px body, 180px section nav, 20x24 content padding, 16px columns. Dense optional sections keep help on demand and safety visible.

Draft boundaries: form authors a bounded document; JSON syntax is valid YAML. Manual source editing retains exact text, comments, unknown content and large scalars; Form then blocks instead of parsing/rebuilding. This mock does NOT claim AST-level bidirectional lossless patching. Raw source and structured draft never persist. Only explicit mode preference is stored. Per-version subresource/column differences, full schemas and unsupported shapes require source-only editing. Production must use existing leaf-level AST contract, preserve unedited siblings, default omission, comments and scalar types, sanitize sensitive annotation projections, and apply revision-aware RBAC/admission checks. Arbitrary sensitive source/import is outside this capture fixture.

Consequences: schema changes can prune stored fields; served changes break clients; webhook failures block access; storage changes require migration. Review is local, destination-aware and non-mutating. No live cluster, companion controller, service, certificate, migration, status write, permission or health claim.
