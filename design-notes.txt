CloudNativePG editor study — issue 333 — design for review, not shipped code

Sources: CloudNativePG 1.27 API https://cloudnative-pg.io/docs/1.27/cloudnative-pg.v1/ and failover https://cloudnative-pg.io/docs/1.27/failover/ . Release source snapshot https://github.com/cloudnative-pg/cloudnative-pg/tree/8b442dcc3d2390e891ec4a53fe576fe9936dfa08 . Approved frame/workflow: omniviewdev/omniview#249; plugin PR72 and PR74. All 10 resource kinds use postgresql.cnpg.io/v1. ClusterImageCatalog is cluster-scoped; all other kinds here are namespaced. Discovery, verbs, RBAC, controller installation and PostgreSQL compatibility must independently qualify production authoring. Database/Publication/Subscription need compatible controller and PostgreSQL features. Quorum is experimental in 1.27 and controller-managed.

Ownership: optional CloudNativePG add-on provider, not Kubernetes-plugin hardcoded OSS forms. Host owns destination, shared manifest lifecycle, revision checks and mutation routing. Provider owns resource semantics and applicability. No provider is installed by this mock.

Common controls: resource name -> metadata.name; destination -> metadata.namespace, omitted for ClusterImageCatalog. Identity locked during Edit. Every displayed field carries its exact spec path. fields.json is full machine-readable label/control/path mapping (paths are relative to spec). Number controls emit numbers; boolean choices emit booleans; quantities remain strings; untouched optional fields stay omitted. No guessed workload/image/storage default. Reference options show names only, never resolved credentials.

Cluster: instances integer; imageName explicit image; storage.size and storage.storageClass strings; resources.requests.cpu/memory exact quantity strings; failoverDelay integer seconds; primaryUpdateStrategy supervised/unsupervised; bootstrap.recovery.backup.name existing Backup reference name. Recovery bootstrap is locked in edit, not an in-place restore. Additional synchronous count -> postgresql.synchronous {method:any,number:<integer>,dataDurability:required}. Do not imply synchronous configuration guarantees all writes. Bootstrap alternatives and advanced resource settings are source-only; preserve whole source instead of coercing. Existing imagePullPolicy is immutable and not exposed for edit. Storage shrink/delete/recreate is never offered as a guided shortcut. Controller can create Pods/PVCs/Services/Secrets; review names that consequence. Operational connection shows replication/promotion boundary, never patches status.targetPrimary. Supported installed CNPG action provider must refresh target and permissions; manual promotion can lose data and disrupt writes.

Pooler: cluster.name same-namespace reference; type rw/ro/r; instances integer; pgbouncer.poolMode session/transaction; pgbouncer.paused boolean. Parameter rows key=value -> pgbouncer.parameters string map. Pooler name must not equal Cluster name. Pause stops new connections after existing queries finish; transaction pooling affects session semantics. Templates/auth-query pairing remain source-only and need installed-version admission validation. No authentication query or credentials are invented.

ScheduledBackup: cluster.name; six-field seconds-first schedule (not Kubernetes five-field cron); method volumeSnapshot/plugin/barmanObjectStore; suspend/immediate booleans; backupOwnerReference none/self/cluster. Parameter rows -> pluginConfiguration.parameters; pluginConfiguration.name is source-only for this kind. Snapshot/backup/controller support must be checked. Owner choice governs generated resource garbage collection, not physical backup retention. Existing generated Backup is an inspector, not editable duplicate schedule.

ImageCatalog and ClusterImageCatalog: images[0].major integer >=10 and images[0].image explicit string. Additional rows use '<major> <image>' -> images[i].major/image. Scope differs visibly. Production must validate unique majors, 1–8 images, extension compatibility and image suitability. Catalog changes can cause dependent clusters to roll; no image existence check is claimed.

Database: cluster.name, immutable SQL name, owner, ensure present/absent, databaseReclaimPolicy retain/delete, immutable encoding, connectionLimit integer. Extension rows -> extensions[i] {name,ensure:present}; schema objects and extension version/absence remain source-only. Immutable template/locale/provider fields stay in source; no conversion/delete/recreate shortcut. PostgreSQL locale features depend on major version. ensure absent and delete reclaim policy can remove data; retain is not a backup.

Publication: cluster.name, SQL name, dbname, target.allTables boolean, publicationReclaimPolicy retain/delete. Selected table rows -> target.objects[i].table.name; remove allTables when selecting tables. Schema/column filters and WITH parameters remain source-only. All tables includes future tables. No claim that table permissions, replica identity or replication settings are valid.

Subscription: cluster.name, SQL name, dbname, publicationName, externalClusterName, publicationDBName, subscriptionReclaimPolicy. Parameter rows -> parameters string map. Source publisher is a Cluster externalClusters definition reference, not a raw connection string. Most CREATE SUBSCRIPTION parameters cannot change later; guided edit conservatively locks cluster/name/dbname/externalClusterName. Exact mutable-parameter applicability requires controller/PostgreSQL validation. It must not silently promise ignored changes applied.

Backup submission: cluster.name, method, target primary/prefer-standby, online boolean and pluginConfiguration.name. Parameters -> pluginConfiguration.parameters. Explicit Review never submits. Offline snapshots can suspend database activity; backup can consume IO/storage and incur charges. Existing request fields lock and review disables in Edit. Generated inspector shows ScheduledBackup parent link boundary. FailoverQuorum inspector identifies controller/primary ownership and observed freshness unavailable; no Create/Edit/status mutation. Real object values and reconciliation outcomes are not fabricated.

Frame/control reuse: faithful isolated HTML composition, not shipped React. Compose installed base-ui Dialog, FormField/Input, Select, NumberInput, SegmentedControl, Tooltip/Popover, Collapsible, Table and Buttons; source should reuse host Monaco. 1000x700, 32px controls, 13px text, 20x24 content padding, 16px gaps. No new generic primitive required. Named mock skill unavailable; approved #249 interactive HTML workflow used. web-design-guidelines actual source fetched and applied to known prototype: semantic buttons, labeled fields, visible focus, native selects, explicit destination, internal scroll, no animation, live errors, click/focus/hover help and Escape. Help details remain outside form flow.

Draft safety: form and source display one draft. JSON is valid YAML and preview uses nested manifest objects, not flattened dotted properties. Any manual source change retains exact raw text and disables Form, avoiding fake lossless parsing. Raw invalid comments, integer 9007199254740993 and invalid array syntax retained in actual browser check. This mock does not demonstrate supported YAML-to-form parsing/AST patching; production must reuse host AST preservation. Only mode preference persists under mock333-mode; no draft persists. No credentials are supplied, fetched, logged or captured. Do not paste credentials into this standalone study. No live mutation endpoints exist.

Evidence: checks.json named booleans plus screenshot filenames; screenshots show every kind, nine edit surfaces, initial, local required error, help, replication/action boundary, non-mutating review, generated Backup, five capability states, unsupported source and narrow fit. Browser used isolated issue-333/chrome-profile, 1440x900 at device scale 1.25, plus 780x760 narrow. Real clicks, typing, selects, add/remove and keyboard Escape drove states. All images visually inspected in review-sheet.png. Synthetic fixtures do not prove production admission/controller behavior.

Limits needing production design review: no live discovery/admission/permission evaluation; no fresh resource load or revision conflicts; source editing intentionally locks guided form; add-row text needs richer typed-row composition before production; validation is local bounded checks, not complete schema validation; most advanced fields are source-only. Source previews containing secrets would require separate redacted projections in production. No raw sensitive view captured. Designs await user review; no issue checkbox checked or issue closed.
