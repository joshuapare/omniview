Gateway API v1.4.0 — review proposal, not shipped code

Scope: all nine issue294 resource kinds. Standard: GatewayClass/Gateway/HTTPRoute/GRPCRoute/BackendTLSPolicy v1; ReferenceGrant v1beta1. Experimental: TCPRoute/TLSRoute/UDPRoute v1alpha2. Installation, discovered versions, verbs and controller feature support must gate actual provider activation.

Ownership: optional Gateway API add-on editor provider, not nine hardcoded Kubernetes built-ins. Provider gets host draft/lifecycle and reference adapter. GatewayClass cluster-scoped and admin-only. All others namespace-scoped. Identity locks on edit; controllerName immutable. Status stays controller-owned. Managed objects use inspect boundary. No delete/recreate shortcut. ReferenceGrant has no status.

Controls: faithful isolated HTML composition, not shipped React/base-ui. Reuse Dialog, SegmentedControl, FormField, Input, NumberInput, Select/Combobox, Table, Collapsible, Tooltip/Popover, TagInput. No new generic primitive proposed; listener, route, TLS and permission semantics stay in provider. Existing #249 compact frame applied. Visual review used web-design-guidelines skill and actual current guideline URL.

Namespaced backend references require matching target-side grant; Gateway admission remains independent. TLS references never resolve secret/certificate bytes.
