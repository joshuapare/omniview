ISSUE 272 — storage.k8s.io design review
Scope: six kinds, native provider. Standalone HTML/CSS composition, not shipped React/base-ui. All data synthetic. No API calls, credentials, real authorization or CSI capability checks.

Primary sources: Kubernetes v1.35.0 OpenAPI https://github.com/kubernetes/kubernetes/blob/v1.35.0/api/openapi-spec/swagger.json#L89841-L94876 ; validation https://github.com/kubernetes/kubernetes/blob/v1.35.0/pkg/apis/storage/validation/validation.go ; v1 types https://github.com/kubernetes/kubernetes/blob/v1.35.0/staging/src/k8s.io/api/storage/v1/types.go . Read issue262, issue249 and plugin PR72/74. v1 baseline; VolumeAttributesClass retains v1beta1, no v1alpha1.

FIELD / CONTROL / OWNED PATH
Common: Name text -> metadata.name, locked on edit. Labels/annotations/ownerReferences/finalizers remain source-only, not a guided patch. Namespace fixed destination for capacity only. Version/kind selected by provider discovery, never inferred permission.
StorageClass: Provisioner text -> provisioner; string key/value add/remove -> parameters; reclaim choice -> reclaimPolicy; binding choice -> volumeBindingMode; omitted/true/false choice -> allowVolumeExpansion; comma tokens -> mountOptions[]; comma zones -> allowedTopologies[].matchLabelExpressions[{key:topology.kubernetes.io/zone,values:[]}]. Create has no executable defaults. Edit locks provisioner, parameters, reclaimPolicy and volumeBindingMode. Expansion/mount/topology mutable; name immutable. No implicit PVC/PV or default-class annotation. Delete consequence visible in review; invalid mount options can fail mounts and are not validated server-side.
VolumeAttributesClass: CSI driver text -> driverName; required nonempty string pairs -> parameters. Both immutable. New class needed for attribute change; separate PVC spec.volumeAttributesClassName change applies it, no automatic mutation. Parameter constraints: <=512 entries, <=256KiB total, nonempty keys. Mock checks presence/empty keys; authoritative driver validation unavailable. Metadata-only edit remains possible in implementation, source-only here.
CSIDriver: Name -> metadata.name (driver identity). Capabilities choices -> spec.attachRequired, spec.podInfoOnMount, spec.fsGroupPolicy, spec.storageCapacity, spec.requiresRepublish, spec.seLinuxMount; lifecycle checkboxes -> spec.volumeLifecycleModes[]. Attach/lifecycle immutable; remaining listed choices mutable in baseline. Omission distinct from false. Token audience/expiration rows -> spec.tokenRequests[].audience and .expirationSeconds (int64, not actual credentials or TokenRequest resource). Secrets choice -> spec.serviceAccountTokenInSecrets requires tokenRequests. Interval -> spec.nodeAllocatableUpdatePeriodSeconds >=10; MutableCSINodeAllocatableCount gate required. Installer-managed branch refuses direct edit. Manual administrator branch assumes independently confirmed installation ownership, never installs a CSI driver. Driver capabilities are claims, not verification.
CSINode: read-only node registration table -> metadata.name, spec.drivers[].name,nodeID,allocatable.count,topologyKeys; ownership -> metadata.ownerReferences to Node. Kubelet/node-driver registrar owns it. No Create/edit/status action.
CSIStorageCapacity: namespaced read-only report -> storageClassName, capacity, maximumVolumeSize,nodeTopology; source-only selector expression precision; unset topology means no node access, empty selector means all nodes. Unset capacity unavailable; zero/missing suitable report prevents scheduling with checks. Driver/provisioner owns report; no reservation or provisioning success inferred.
VolumeAttachment: inspect -> spec.attacher,nodeName,source.persistentVolumeName; inlineVolumeSpec alternative source-only (migration/system path). Controller owns spec; external-attacher owns status.attached,attachError,detachError,attachmentMetadata. Opaque metadata redacted; no status edits or manual detach. No implied mutation action.

REUSE
Compose existing semantic Input/Select/Checkbox/Button, form labels, tabs/sidebar, table, alert, tooltip/popover, repeatable key/value rows, footer/review shell. No new base-ui primitive. Native storage forms belong to built-in Kubernetes provider; third-party driver parameter schemas can enrich opaque string controls via addon provider contract, never claim capability from schema. Field ownership/immutable predicates stay resource-side. #263/#264 own shared contract proposals.

LIMITS / REVIEW DECISIONS
Source workspace intentionally source-only: exact unsupported/invalid text retained across switching, including comments and large scalar. No YAML AST parser, bidirectional form/source merge, authoritative serialization, complete metadata UI, parameter size/duplicate/audience/range schema validation or persistent mode preference demonstrated. Form draft and source-only draft are separate; never claim lossless form conversion. Production must reuse approved PR72/74 single AST draft rather than this isolated state model. Source projection is illustrative and partial; no submission. Source editing disables review through an explicit boundary. This is a mock limit, not production behavior. No test proves API permissions, controller readiness, cloud availability or real mutations. Driver reference is editable identifier; fixture does not fabricate discovered choices. Review summaries show consequence/destination, not full patch diff. No approval or shipping claim.
