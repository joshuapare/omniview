Ownership and applicability
An optional KEDA add-on editor provider should own these forms, not Kubernetes built-ins. Require installed matching GVK/schema, verbs and RBAC, compatible operator/scaler support and reference permissions. Installation is not implied by schema discovery. Runtime fixture selectors distinguish missing API, permission denied, unavailable lookup, empty results and owner-managed source. These demonstrate UX only. Production must use the shared capability/provider contracts. No new base-ui primitive needed: Dialog, FormField/Input, Select/Combobox, SegmentedControl, Tooltip/Popover, Collapsible, Checkbox, Button and existing source editor compose the design. Isolated HTML is not shipped React or exact semantic-token wiring.

Field / control / owned path
Common identity: text Name -> metadata.name; namespace context -> metadata.namespace for namespaced kinds only. Lock both during edit. apiVersion and kind fixed. Identity immutability is Kubernetes identity, not a claim all KEDA spec fields are immutable. Admission may add restrictions. status and ownerReferences are never authored.
ScaledObject target text -> spec.scaleTargetRef.name, same namespace, Deployment default by omission. Alternate kind/apiVersion/envSourceContainerName remain source-owned, not silently normalized.
ScaledObject integers: minimum -> spec.minReplicaCount, maximum -> spec.maxReplicaCount, polling seconds -> spec.pollingInterval, cooldown seconds -> spec.cooldownPeriod. Blank means omitted. Cooldown applies to zero only; HPA controls one-to-many scaling.
ScaledObject fallback integer pair -> spec.fallback.replicas and spec.fallback.failureThreshold. Pair required together; no fallback on ScaledJob. Behavior enum, initialCooldownPeriod, idleReplicaCount (only zero supported), restoreToOriginalReplicaCount, HPA name/behavior and scalingModifiers stay source-owned; production advanced composition must patch exact paths without touching siblings.
ScaledJob image -> spec.jobTargetRef.template.spec.containers[0].image with explicit worker name and restartPolicy Never in this new draft subset. No guessed image. This is a JobSpec template, not existing Job reference. Min/max/poll -> spec.minReplicaCount, spec.maxReplicaCount, spec.pollingInterval. Rollout select -> spec.rollout.strategy, omission/default/gradual distinct. Default can terminate existing Jobs on update; gradual retains existing Jobs. Job parallelism/completions/backoff/deadline, history limits, rollout propagationPolicy, envSourceContainerName and scalingStrategy remain source-owned.
Both scaling kinds: RabbitMQ queue -> spec.triggers[0].metadata.queueName; queue mode -> .metadata.mode: QueueLength; messages per replica -> .metadata.value STRING; activation -> .metadata.activationValue STRING; scaler -> .type: rabbitmq; authentication name/scope -> .authenticationRef.name and .kind. No sensitive host literal field. Credential resolution never occurs. Other scalers, metricType, trigger name, useCachedMetrics and multiple triggers require source. Add trigger explicitly opens YAML, never inserts a fake trigger or claims a guided repeatable-row implementation.
TriggerAuthentication and ClusterTriggerAuthentication: parameter/name/key -> spec.secretTargetRef[0].parameter, .name, .key. Remove mapping explicitly removes mapping only. Provider select -> spec.podIdentity.provider. Provider configuration validity is not proved by selecting its name. Namespaced authentication must match consuming namespace. Cluster authentication can serve all namespaces; its Secret namespace comes from KEDA operator namespace / KEDA_CLUSTER_OBJECT_NAMESPACE, not consuming workload namespace. Environment mappings, boundServiceAccountToken, provider-specific identities and Vault/Azure/AWS/GCP external-store structures remain advanced/source-owned. Secret values are never loaded or shown. Sensitive imports/raw credential edits are intentionally not offered in mock.
Pause checkbox -> metadata.annotations["autoscaling.keda.sh/paused"] string "true"; unchecked removes that key, not all annotations. Resume means remove supported pause configuration. paused-replicas and scale-in/out-specific annotations require source/admission-aware review, not fabricated action success. Generated HPA/Jobs action is an honest unavailable inspector connection; no generated-spec Create/Edit surface.

Source and privacy limits
Form-generated subset shares draft with YAML. Once manually edited, exact raw source remains unchanged and Form/review lock. Unsupported/invalid YAML, comments and integer 9007199254740993 were retained verbatim in browser. This does not prove arbitrary AST roundtrip editing. Authentication YAML is a read-only safe projection; no credentials or annotations enter this bounded prototype. Projection is never parsed back or submitted. Existing-resource fixture fields do not prove unknown-field preservation, revision-safe patches, server admission or status behavior. Production must retain full original source, resourceVersion and sibling nodes through shared draft engine. Only explicit view preference persists; values stay in memory and vanish on reload.

Remaining review decisions
Guided coverage intentionally focuses on RabbitMQ queue scaling, Deployment targets, one-container Jobs, Secret mappings and basic workload identity. Every assigned kind has a distinct interface, but this is NOT exhaustive guided coverage of all scaler/provider/advanced schemas. Source-owned boundaries are visible and documented, not placeholders pretending to save. Production must add AST-backed general source access, complete branch validation, real reference pickers, focus trap/close restoration and conflict-aware write checks before implementation acceptance. Mock never applies anything and cannot establish production safety or permission.
