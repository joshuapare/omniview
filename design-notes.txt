BOUNDARIES
No spec field is declared immutable in this API snapshot. Identity is immutable Kubernetes metadata. Source/output/rule edits still depend on admission, ownership, verbs and controller policy. GitOps-owned fixture blocks direct guided edits; production must route to owner repository or explicit conflict-aware override flow. Generated ExternalArtifacts are inspect-only here; generated status and artifact bytes are never entered by users. Changes to output names and removal can disrupt consumers. No source files are fetched and no file-match/output-content prediction is claimed. Cross-namespace source references are explicit; actual access depends on source-watcher configuration and permissions. No source-controller, source-watcher, companion ExternalArtifact or consumer is secretly created by Review.

INTERACTION & LOSSLESS LIMIT
Interactive standalone HTML composition, not React/base-ui implementation. One bounded in-memory draft emits YAML using JSON-compatible flow values. Untouched Form/YAML switches preserve that draft. Manual source edits remain exact verbatim, including invalid text/comments/unknown content; all guided conversion and review then lock. This intentionally does NOT claim safe AST edits after arbitrary YAML import. Production must integrate existing lossless manifestDraft AST patching, preserve unknown fields, comments, exact numeric/scalar types and siblings, and retain source on conflicts. Only explicit mode preference persists, never drafts. Switching fixture intent intentionally loads a new fixture and is not product navigation.
No raw sensitive fixture values, annotations, credentials or imported live config used. No live calls or mutations. Generated metadata values omitted rather than fabricated.

REUSE & PROVIDER
Flux add-on editor provider should register exact GVK and capability/ownership predicates, not Kubernetes built-in hardcoding. Reuse shared Dialog, SegmentedControl, FormField, Input, Select/Combobox, TextArea, Tooltip/Popover, Buttons, and repeatable row composition. Existing Monaco/manifest draft is production source surface; textarea here is a faithful isolated mock boundary. No new generic primitive or base-ui release proposed. Structural graph belongs in Flux adapter, not base-ui. Semantic colors should replace mock palette during implementation.
